## 重要教训

### auth.json 双 provider 导致 401

`hermes-agent` 的 `minimax-cn` provider 调用 `api.minimaxi.com`，但 `auth.json` 同时注册了 `minimax`（`api.minimax.io`）。任务若选了错误的 provider，key 在该端点被拒，5 次重试后放弃。

**任何 scraper 任务崩溃，先查 `auth.json` 是否有多余 provider。**

### The Wire 无法绕过

- RSS 返回 HTML 而非 XML
- /category/reviews 返回 404
- 无 RSS，无公开内容
- 跨站搜索（web_search）也未找到有效评论

**结论：The Wire 标记 `status=paywalled`，不重试。**

### Kanban 积压问题

每次 `kanban-batch-scrape.py` 运行会新建 43 个任务，历史任务（◻ todo 状态）不会自动清理。跑新批次前必须先归档旧 ◻ todo scraper 任务，只保留 done/running/blocked 的。

## 现有 Skill vs 新方案对比

### 旧方案（avant-garde-daily-recs.md）
- `delegate_task(tasks=[...])` 并发 subagent
- 每 agent 独立巡检 3-4 个站点
- 主 session 汇总结果
- **问题**：每次只有十几个候选，数量有限

### 新方案（music-daily-recs.md）
- `kanban-batch-scrape.py` 创建 43 个独立 scraper 任务
- 全部 parallel，受 dispatcher 并发数控制
- aggregator 汇总所有输出
- **优势**：覆盖站点更多，结果更全
